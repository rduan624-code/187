# A/B/C/D 升级后端契约

已确认：A 板 XC7VX690T 运行 MicroBlaze 和 lwIP，接收 MLC UDP；A 升级自身，B/C/D 通过拟新增的 AXI 控制寄存器、共享数据缓冲、FIFO/Aurora 通路升级。B/C/D 对端包含接收与缓存逻辑以及 BPI Flash。A 板本地 Flash 接口尚待手册和设计确认，不根据远端 Flash 类型推定 A 板接法。

## 共用状态机

`IDLE → RECEIVING → PREPARING → WAIT_BURN → BURNING → DONE / FAILED`

| 阶段 | 软件职责 | 后端必须保证 |
|---|---|---|
| RECEIVING | 逐帧 0088，A DDR 暂存，长度/编号/累加和检查 | 此时不触发擦写 |
| PREPARING | 调用 prepare 一次，再反复调用 prepare_step | A：检查本地映像及元数据区容量；B/C/D：传输完整摘要和文件、等待目标校验和容量确认 |
| WAIT_BURN | 将 0089 成功报告交给网络栈，等待本地发送队列清空 | 保留镜像和目标资源，尚不擦写 |
| BURNING | 调用 begin 一次，再反复调用 step；上报 008A | A：本地持久化和读回验证；B/C/D：发起远端烧写并等待远端真实进度/结果 |
| DONE | 成功进度编码 4，保留结果供最后帧重传查询 | 镜像和摘要均已验证持久化、资源已释放 |
| FAILED | 失败报告；操作中的后端先 abort | 不留有可继续访问已释放缓冲的 DMA/硬件任务 |

`prepare/prepare_step/begin/step/abort` 见 `src/upgrade_board.h`。所有函数必须有界、非阻塞，不可等待 Flash 完整擦写或 Aurora 永久 ready。成功返回网络发送仅表示 lwIP 已接纳，不等于 MLC 已收到；ICD 没有定义 REPORT ACK。

准备/烧写超时触发 abort 并报告失败。abort 必须在返回前确保共享缓冲不会再被旧会话访问；若真实硬件无法同步取消，需在实现驱动时扩展为可轮询取消状态，不能用一个空函数假装停止。B/C/D 对端也必须保留会话/事务标识，避免把上一轮晚到的结果当成本轮成功。

## 待硬件确定的接口，不在本版猜测寄存器

### A 本地后端

- Flash 总线类型、位宽、地址窗口、型号、擦写粒度与命令集。
- 启动映像、更新映像、保护区、摘要区地址及可用容量。
- 当前 MicroBlaze 指令/数据与升级目标是否共用启动介质；擦写期间执行必须存续。
- 忙/失败状态、超时、回读验证、复位与重新配置流程。当前没有自动重配置动作。

### B/C/D 远端后端

- AXI 基址、寄存器宽度/端序、命令与状态字段、门铃/中断或轮询机制。
- 目标选择 0x72/73/74 与物理 Aurora 链路的真实映射。
- 共享缓冲地址、容量、对齐、长度单位、消费完成标记、双缓冲所有权。
- 缓存 flush/invalidate 范围及屏障：CPU 提交数据前确保硬件可见，读硬件结果前确保 CPU 看到新值。
- FIFO 容量与流控；链路 ready、丢包、重传、复位与取消机制。
- 内部报文/命令至少需表达目标、事务标识、摘要、文件总长、分块偏移/长度，以及远端接收确认、校验结果、空间状态、烧写进度和终态。这里是接口需求清单，不是已确定的 wire/register 布局。
- 远端必须区分“缓存接收完成”和“Flash+摘要写入完成”，并提供可关联当前事务的反馈。

在用户提供实际寄存器和内部通信定义前，`upgrade_board.c` 中的 remote 接口 不操作现有以太网 DMA、不复用 Debug Bridge、不复用 GPIO JTAG，也不编造 AXI 控制地址。

## 已读取 BSP 的事实

- standalone 6.8，MicroBlaze v11.0，编译参数含 `-mlittle-endian`；ICD 编解码使用显式大端，不能直接强转网络字节为结构体。
- lwip202 1.2（lwIP 2.0.2），RAW API，`NO_SYS=1`，UDP 开启，BSP 原配置 DHCP 开启。升级启用时应用选择静态 IP，无需手改 BSP 生成文件。
- 处理器和 AXI Timer 时钟 100 MHz；DDR `0x80000000..0x9FFFFFFF`，512 MiB；数据缓存开启。
- 以太网 `0x40C00000`，与其连接的 AXI DMA `0x41E00000`；这些是网络通路，不是升级 Aurora 专用传输。
- GPIO0..5：`0x40000000..0x40050000`（各窗口 64 KiB）；Debug Bridge `0x44A00000`。
- Timer `0x41C00000`，中断控制器 `0x41200000`，UARTLite `0x40600000`。
- BSP 未提供独立的升级 AXI 控制/Aurora 软件映射或 Flash 驱动定义；这一观察不能证明硬件内部不存在未映射模块。

`docs/bsp-reference/` 保留上传 BSP 的三份原始配置作为参考，不取代完整 BSP。Flash 芯片手册后续接入。

## BD 分卷读取后的核对结果

三个 RAR 分卷已成功读取，归档共 1377 个条目；提取并静态检查 `design_1.bd` 及其导出的 `design_1_bd.tcl`，没有执行附件中的 Tcl。两份参考文件保存在 `docs/bd-reference/`，其引用的 IP 文件仍需原始完整 Vivado 工程，不能声称单独 Tcl 已验证可重建工程。

- 器件 `xc7vx690tffg1927-2`，设计工具 Vivado 2018.3；顶层组件和地址分配与 BSP 相符。
- 现有网络外部接口为 RGMII/MDIO，此外有 DDR3、UART、六路 GPIO。协议所述光纤链路与这份 BD 中的 RGMII 接口是不同层面的信息，现阶段软件复用实际 AXI Ethernet。
- AXI Interconnect 配置 7 个 slave-side 接入口和 13 个 master-side 接出口，现有以太网 DMA 的 MM2S/S2MM/SG 通路已连接到以太网和内存。
- Debug Bridge 为 Xilinx debug_bridge 3.0，配置 `C_DEBUG_MODE=2`、`C_BSCAN_MUX=2`。这些参数不能代替 Flash 或 Aurora 升级控制寄存器说明。
- 在这份顶层 BD 及其导出 Tcl 中没有发现 Aurora IP、独立升级控制 IP、BPI/EMC/SPI Flash 控制 IP或相应升级外部端口。只能据此判断上传 BD 尚未包含图示新增升级通路，不能排除工程其他顶层 RTL 的接口。
- 因此本版的软件后端接口已覆盖四目标，但现有 BD 不能单靠软件直接完成图示 B/C/D 升级链路；需后续新增/提供硬件控制、共享缓冲、FIFO/Aurora 与远端 Flash 状态反馈。
